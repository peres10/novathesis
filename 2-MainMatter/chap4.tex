\section{Proposed System Architecture}
\label{sec:sol_architecture}
\ntindex[Template]{}
    {
        The proposed platform follows a three-layer architecture that separates user interface, application logic and data persistence, while remaining compatible with the technologies and requirements established in earlier chapters.
        At a high level, this structure is designed to support incremental evolution from a prototype to a long-lived institutional system, without forcing disruptive changes to the overall desgn.
    }

    {
        At the presentation layer, a React-based web application delivers role-specific dashboards for students, company representatives, professors, coordinators, and the secretariat.
        The UI will be composed of reusable components for common views, which simplifies maintaining consistent behavior and visual language across roles.
        For student authentication, the platform will integrate with the university's identity provider using OAuth, so that students
        can log in with their institutional accounts and their profile and enrollment information can be imported without manual registration.
    
    }

    {
        The application layer exposes a REST API that encapsulates all business logic. 
        During the initial prototyping phase, this layer can rely on managed services (such as Supabase) for basic authentication
        and CRUD operations, so that core workflows can be validated quickly with real users.
        As the system stabilizes, a Spring Boot-based backed assumes responsibility for the domain logic.
    }

    {
        The data layer is implemented with PostgreSQL, using a relational schema such as the one described in Section 4.3.
        Referential integrity is enforced with foreign keys to prevent inconsistent states, and \gls{RLS} is used to constrain which rows each role can access.
        External services complement this layer: a transactional email provider is used for reliable delivery and tracking of notifications, and an object storage
        service holds upload documents such as CVs, protocols and reports. 
    }

    {
        Together, these elements allow AI-assisted prototypes to be refined into a secure, maintainable platform rather than being discarded.
    }
